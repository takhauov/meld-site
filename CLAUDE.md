# MELD — сайт-визитка. Контекст для Claude Code

Этот файл — сводка состояния проекта на момент переноса работы из обычного
чата в Claude Code. История переписки не переносится, поэтому здесь —
решения, которые не видны напрямую из кода, и список того, что осталось
сделать. Читай этот файл в начале каждой сессии.

## Что это за проект

Многостраничный статический сайт бренда MELD (Ольга — владелица бренда):
профессиональное оборудование для строительства, отделки и кузовного ремонта.
Два товарных направления: безвоздушные окрасочные аппараты (модели MELD 190S,
MELD 498) и споттеры для кузовного ремонта (модель MELD 90E LSD).
Характеристики всех трёх моделей подтверждены заказчицей 2026-08-11
(см. раздел «ЧТО ТОЧНО НУЖНО СДЕЛАТЬ» — расхождения, которые стоит уточнить).

Сайт собирается статическим сборщиком на чистом Node.js без зависимостей —
никакого React/фреймворков. Tailwind используется только для стилей и
собирается заранее в один файл `assets/styles.css` (см. «Решено 2026-09-11» —
до этой даты был подключён через CDN, теперь CDN на сайте нет вообще).

## Структура

```
src/layout.html         общий каркас: шапка, подвал, весь JS, разметка.
                        Правится ОДИН раз для всего сайта.
src/pages/*.html        содержимое страниц. Файл начинается с 4 строк
                        параметров (title/description/url) и разделителя ---,
                        дальше обычная HTML-разметка без <head>/<body>.
src/tailwind-input.css  исходник стилей для Tailwind (custom CSS + три
                        директивы @tailwind) — правится вместо старого
                        инлайнового <style> в layout.html.
tailwind.config.js      цветовая палитра и настройки Tailwind (раньше был
                        инлайновый tailwind.config в layout.html).
tailwindcss.exe         сама программа-сборщик стилей, скачана отдельно
                        (см. «Решено 2026-09-11»), в git не попадает.
assets/                 картинки (.webp) + собранный assets/styles.css.
build.js                сборщик. Запуск: node build.js — сначала пересобирает
                        стили через tailwindcss.exe, потом страницы.
docs/                   ГОТОВЫЙ САЙТ — то, что отдаёт GitHub Pages
                        (репозиторий настроен отдавать сайт из /docs).
                        Руками не редактируется, полностью пересоздаётся
                        сборщиком.
preview/                те же страницы, но картинки зашиты в HTML как
                        base64 — можно открыть двойным щелчком без сервера,
                        для просмотра результата. На хостинг НЕ грузится.
README.txt              инструкция для человека (не для агента), там же
                        описана публикация на GitHub Pages.
```

Страницы сейчас: `index.html` (главная), `catalog.html` (витрина каталога),
`catalog-airless.html` (окрасочные аппараты), `catalog-spotter.html`
(споттеры), `privacy.html` (политика конфиденциальности — реальный текст,
см. «Решено 2026-08-13»), `consent-pd.html` (согласие на обработку ПД),
`consent-news.html` (согласие на рекламно-информационные сообщения).

## Как вносить изменения — обязательный порядок

1. Править только в `src/layout.html` (общее) или `src/pages/*.html`
   (конкретная страница). Никогда не редактировать `docs/` напрямую —
   любые правки там исчезнут при следующей сборке.
2. Запустить `node build.js` — пересоберёт `docs/` и `preview/`,
   обновит `sitemap.xml` и `robots.txt`.
3. Если менялась картинка — дать файлу новое имя (например, добавить
   `-v2`), а не перезаписывать старое: иначе у пользователей, уже
   заходивших на сайт, картинка не обновится из кеша браузера.
4. Проверить свежий `docs/index.html` (или `preview/index.html`) перед
   коммитом.
5. Git: `git add . && git commit -m "..." && git push`. GitHub Pages
   подхватит `docs/` через 1–2 минуты.

Домен заменён на реальный 2026-08-13: `const DOMAIN = 'https://meld-tools.ru'`
в начале `build.js` (из него собираются sitemap и canonical-ссылки). Домен
куплен заказчицей, но к хостингу пока не подключён — подключит сама позже,
когда закончатся остальные доработки. До подключения сайт публикуется
только по адресу GitHub Pages (см. «Публикация» ниже).

## Визуальная система (важно не нарушить логику, даже если просят разное)

Собрано на основе Behance-референса про автосервис, адаптировано под
цвета MELD (заказчица явно просила: "цветовая гамма текущая, без замены
цвета" — прежде чем менять палитру, переспросить).

- Тёмная база `#0D1117` / панели `#161B22`, светлые вставки `#F7F8F9` —
  секции чередуются тёмная/светлая/тёмная...
- Единственный цветной акцент — бирюзовый `#14A098` / `#0E7C7B` (снят с
  корпуса реального аппарата, это сознательный выбор, не украшение).
- Шрифт — Onest (кириллица родная, в отличие от Inter, который заказчица
  отклонила). Не менять шрифт без явной просьбы — перебирали уже 4
  системы дизайна, каждый раз возвращались к текущей палитре.
- Межстрочный интервал заголовков: `.hd-lg` (крупные) — 1.2, `.hd`
  (средние/мелкие) — 1.35. Это финальные значения после нескольких
  итераций, не трогать без причины.
- Диагональные "клинья" с фото в hero: срез — трапеция (не треугольник!),
  проверено расчётом, что фигура человека попадает в видимую область при
  любой ширине экрана. Если будут новые фото для hero — пересчитывать
  видимую зону среза, не просто менять src.
- Все внешние ссылки (Wildberries/Ozon/Я.Маркет) уже стоят и рабочие.
- Движение: `.reveal`/`.stagger` — появление при скролле через
  IntersectionObserver, отключается при `prefers-reduced-motion: reduce`.
  `.ph:hover img` — зум фото на 5% внутри неподвижной рамки (единственный
  эффект наведения, который сейчас в проекте — экспериментировали с
  проявлением фото и разбивкой заголовков по словам, оба откатили по
  просьбе заказчицы).
- **Бейдж на карточке товара** (класс `.nameplate` в `layout.html`): форма
  и отсутствие иконки всегда одинаковые во всех каталогах. Positioning
  адаптивный: `top-4 left-4` на мобильных (16px от края), `sm:top-10
  sm:left-10` от `sm`-брейкпоинта (40px, равно ширине рамки-паддинга
  `relative p-5`) — на мобильных экранах уменьшенный отступ нужен, чтобы
  бейдж не перекрывал сам товар на фото (на десктопе места больше, там
  просто отступ = ширина рамки). Меняется только цвет: `.nameplate--red`
  (`#E23E3E`) или `.nameplate--teal` (`#14A098`). При добавлении бейджа на
  новый товар — спросить заказчицу, красный или бирюзовый, форму не обсуждать.
  Раньше пробовали градиент, полупрозрачный фон и звёздочку-иконку — все
  варианты откатили (низкий контраст текста, иконка не совпадала по линии
  с текстом), сейчас плоская сплошная заливка и просто текст.
- **Шапка сайта** (`#site-header` в `layout.html`) прилипает к верху при
  прокрутке — реализовано через JS-класс `.is-fixed` (`position: fixed`),
  НЕ через `position: sticky`. `position: sticky` не работает, потому что
  `.panel` (общая обёртка страницы) держит `overflow: hidden` — это нужно
  для скруглённых углов и наклонных "клиньев"-фото в hero, и его нельзя
  просто убрать без риска сломать вёрстку. `#header-spacer` сразу после
  `</header>` подставляет высоту хедера в поток при переключении на fixed,
  чтобы контент не прыгал. Пока закреплена — фон почти прозрачный (15%,
  `rgba(13,17,23,.15)` + блюр), при наведении курсора становится полностью
  непрозрачной (100%). Скругление углов `.panel` и `.is-fixed` синхронно
  уменьшено до 2px (масштаб бейджей `.nameplate`) — раньше было 28px,
  заказчица явно попросила единый острый стиль по всему сайту, а не только
  у хедера. Перебирали несколько вариантов (обычная плавающая карточка
  28px, только верхние углы скруглены, плавающая кнопка меню вместо
  шапки, тёмная непрозрачная заливка, разноцветный/бирюзовый бегущий
  индикатор) — не подошли, финальный вариант именно этот.
- **Основные CTA-кнопки** («Перейти в каталог», «Получить консультацию» —
  классы `.btn-teal-volume` и `.btn-beam` в `layout.html`): заливка с
  лёгким объёмом (светлая грань сверху, тень снизу, не плоский цвет),
  тёмный текст (не белый — контраст 6,2:1 против 3,2:1, заказчица выбрала
  тёмный), скругление углов 8px, по границе бежит короткий бирюзовый
  светящийся отрезок (46×2px, 10 секунд на оборот, синхронно на соседних
  кнопках). На скруглённых углах у полоски бывают короткие «лучи»
  (жёсткая форма не гнётся по дуге) — заказчица знает и приняла этот
  компромисс: пробовали точку и размытый след вместо полоски, понравилось
  меньше, чем лучи на углах — вернулись к полоске.
- **Раздел «Контакты»** (`index.html`) — двухколоночный: слева блок
  контактов (заголовок «Связаться с MELD» + `dl` с телефоном/почтой/
  мессенджерами/адресом), справа форма «Оставить заявку». Классы
  `.field`/`.form-status`/`.error-text` в `layout.html` существовали в
  CSS ещё до формы (остались от старой формы, которую убрали раньше по
  просьбе заказчицы) — переиспользованы, а не написаны заново.
  Кнопка отправки — те же классы `.btn-teal-volume`/`.btn-beam`, что и
  у «Перейти в каталог»/«Получить консультацию» (заказчица явно попросила
  единый стиль). Нюанс: на светлой секции (`bg-paper` = `#F7F8F9`) при
  наведении фон кнопки уходит почти в белый (`#F5F5F5` у `.btn-teal-volume`
  на hover) — заливка становится почти незаметной на фоне секции, остаётся
  видна только бирюзовая рамка от `.btn-beam`. На тёмных секциях (hero,
  каталог) этой проблемы нет. Заказчица знает и приняла этот компромисс
  ради единого вида кнопок по сайту.

`node build.js` запускает её автоматически первым шагом, отдельно ничего
запускать не нужно. Нюанс: класс `flex-[3]` (им подсвечивается активная
миниатюра в галерее фото) почему-то не подхватывался автосканированием
Tailwind при реальном размере файла `layout.html` (в изолированном тесте
подхватывался нормально, причину до конца не выяснили) — добавлен явно
через `safelist` в `tailwind.config.js`, работает подтверждённо. Остаётся
актуальным: Content-Security-Policy на сайте по-прежнему нет — GitHub Pages
не даёт задавать свои HTTP-заголовки, вернуться к этому вопросу стоит при
переезде на отдельный хостинг с реальным доменом `meld-tools.ru`.

e-mail, сообщение, все три согласия — да/нет) пишется отдельной строкой.
После успешной отправки посетитель видит всплывающее окно
(`#lead-sent-modal` в `index.html`), при сетевой ошибке — текст под
кнопкой. Уведомления в Telegram при новой заявке заказчица попросила
пока не делать (отложено, не забыть предложить позже).

## Стиль общения с заказчицей (по опыту этого диалога)

- Работает в Windows, использует Chrome, открывает файлы двойным щелчком
  — не разработчица. Все инструкции должны быть буквальными
  ("откройте файл X", а не "запустите dev-сервер").
  Пишите жестко без единого литературного эпитета, только точные факты.
- Просит показывать альтернативы и явно указывать, что придумано (не
  подтверждённые данные — помечать в коде комментарием `ЗАМЕНИТЬ` и
  проговаривать в ответе).
- Несколько раз просила "сначала верни как было, потом обсудим" —
  откаты должны быть аккуратными, лучше проверять расчётом/тестом перед
  тем как утверждать "починил".
- Была ситуация, когда бралось на веру визуальное состояние без
  реальной проверки рендеринга — с тех пор: описывать факт (например,
  "было отступов X, стало Y"), не утверждать "теперь идеально" без
  способа это проверить.
