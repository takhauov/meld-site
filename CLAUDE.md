# MELD — сайт-визитка. Контекст для Claude Code

Этот файл — сводка состояния проекта на момент переноса работы из обычного
чата в Claude Code. История переписки не переносится, поэтому здесь —
решения, которые не видны напрямую из кода, и список того, что осталось
сделать. Читай этот файл в начале каждой сессии.

## Что это за проект

Многостраничный статический сайт бренда MELD (Ольга — владелица бренда):
профессиональное оборудование для строительства, отделки и кузовного ремонта.
Два товарных направления: безвоздушные окрасочные аппараты (модели MELD 190S,
MELD 498) и споттеры для кузовного ремонта (пока одна вымышленная модель).

Сайт собирается статическим сборщиком на чистом Node.js без зависимостей —
никакого React/фреймворков, никакого Tailwind (сознательно убрали CDN-версию
на позднем этапе, чтобы не было предупреждения в консоли и не тянуть внешние
скрипты в проде).

## Структура

```
src/layout.html        общий каркас: шапка, подвал, все стили, весь JS.
                        Правится ОДИН раз для всего сайта.
src/pages/*.html        содержимое страниц. Файл начинается с 4 строк
                        параметров (title/description/url) и разделителя ---,
                        дальше обычная HTML-разметка без <head>/<body>.
assets/                 картинки, только .webp
build.js                сборщик. Запуск: node build.js
docs/                   ГОТОВЫЙ САЙТ — то, что отдаёт GitHub Pages
                        (репозиторий настроен отдавать сайт из /docs).
                        Руками не редактируется, полностью пересоздаётся
                        сборщиком.
preview/                те же страницы, но картинки зашиты в HTML как
                        base64 — можно открыть двойным щелчком без сервера,
                        для просмотра результата. На хостинг НЕ грузится.
README.txt              инструкция для человека (не для агента), там же
                        описана публикация на GitHub Pages.
```

Страницы сайчас: `index.html` (главная), `catalog.html` (витрина каталога),
`catalog-airless.html` (окрасочные аппараты), `catalog-spotter.html`
(споттеры).

## Как вносить изменения — обязательный порядок

1. Править только в `src/layout.html` (общее) или `src/pages/*.html`
   (конкретная страница). Никогда не редактировать `docs/` напрямую —
   любые правки там исчезнут при следующей сборке.
2. Запустить `node build.js` — пересоберёт `docs/` и `preview/`,
   обновит `sitemap.xml` и `robots.txt`.
3. Если менялась картинка — дать файлу новое имя (например, добавить
   `-v2`), а не перезаписывать старое: иначе у пользователей, уже
   заходивших на сайт, картинка не обновится из кеша браузера.
4. Проверить свежий `docs/index.html` (или `preview/index.html`) перед
   коммитом.
5. Git: `git add . && git commit -m "..." && git push`. GitHub Pages
   подхватит `docs/` через 1–2 минуты.

Перед первой публикацией: заменить `const DOMAIN = 'https://meld.ru'` в
начале `build.js` на реальный домен — из него собираются sitemap и
canonical-ссылки.

## Визуальная система (важно не нарушить логику, даже если просят разное)

Собрано на основе Behance-референса про автосервис, адаптировано под
цвета MELD (заказчица явно просила: "цветовая гамма текущая, без замены
цвета" — прежде чем менять палитру, переспросить).

- Тёмная база `#0D1117` / панели `#161B22`, светлые вставки `#F7F8F9` —
  секции чередуются тёмная/светлая/тёмная...
- Единственный цветной акцент — бирюзовый `#14A098` / `#0E7C7B` (снят с
  корпуса реального аппарата, это сознательный выбор, не украшение).
- Шрифт — Onest (кириллица родная, в отличие от Inter, который заказчица
  отклонила). Не менять шрифт без явной просьбы — перебирали уже 4
  системы дизайна, каждый раз возвращались к текущей палитре.
- Межстрочный интервал заголовков: `.hd-lg` (крупные) — 1.2, `.hd`
  (средние/мелкие) — 1.35. Это финальные значения после нескольких
  итераций, не трогать без причины.
- Диагональные "клинья" с фото в hero: срез — трапеция (не треугольник!),
  проверено расчётом, что фигура человека попадает в видимую область при
  любой ширине экрана. Если будут новые фото для hero — пересчитывать
  видимую зону среза, не просто менять src.
- Все внешние ссылки (Wildberries/Ozon/Я.Маркет) уже стоят и рабочие.
- Движение: `.reveal`/`.stagger` — появление при скролле через
  IntersectionObserver, отключается при `prefers-reduced-motion: reduce`.
  `.ph:hover img` — зум фото на 5% внутри неподвижной рамки (единственный
  эффект наведения, который сейчас в проекте — экспериментировали с
  проявлением фото и разбивкой заголовков по словам, оба откатили по
  просьбе заказчицы).

## ЧТО ТОЧНО НУЖНО СДЕЛАТЬ (по приоритету)

### Блокирует публикацию
1. **Реальные контакты**: телефон (`+7 900 000-00-00` — заглушка везде,
   минимум 4 места на страницу × 4 страницы), WhatsApp, Telegram, адрес,
   часы работы.
2. **Ссылка на политику обработки персональных данных** — нет вообще,
   юридически обязательна.
3. **Юридический адрес ИП** для подвала (ИП Тарасов В.М., ИНН и ОГРН уже
   есть, адреса нет).
4. **Первое фото hero** — на текущем на корпусе аппарата читается
   "WELD" вместо "MELD" (артефакт нейрогенерации). Нужен новый кадр:
   вертикальный 3:4, минимум 900×1200px.
5. **Характеристики MELD 498** — часть значений (давление 227 бар,
   подача 2 л/мин, сопло 621) сейчас скопированы с 190S и не
   подтверждены. Подтверждено только: вес 15 кг, мощность 1950 Вт,
   шланг 15 м, удлинитель 45 см.

### Важно, но не блокирует
6. **Споттер целиком выдуман** — модель "MELD SP-3200", все
   характеристики (ток 3200А, 220В, 5кВт, 30кг), комплектация (8
   позиций) и 4 вопроса в FAQ написаны мной для заполнения макета.
   Нужны реальные данные и фото. Под карточкой уже стоит предупреждение
   "Характеристики уточняются, актуальные значения — у менеджера".
7. **Фото карточки споттера** — сейчас заглушка вместо картинки.
8. Favicon отсутствует.
9. Страница 404 отсутствует.
10. Формы обратной связи на сайте нет (убрали по просьбе заказчицы) —
    вместо неё везде ссылки на контакты/мессенджеры.

## Стиль общения с заказчицей (по опыту этого диалога)

- Работает в Windows, использует Chrome, открывает файлы двойным щелчком
  — не разработчица. Все инструкции должны быть буквальными
  ("откройте файл X", а не "запустите dev-сервер").
  Пишите жестко без единого литературного эпитета, только точные факты.
- Просит показывать альтернативы и явно указывать, что придумано (не
  подтверждённые данные — помечать в коде комментарием `ЗАМЕНИТЬ` и
  проговаривать в ответе).
- Несколько раз просила "сначала верни как было, потом обсудим" —
  откаты должны быть аккуратными, лучше проверять расчётом/тестом перед
  тем как утверждать "починил".
- Была ситуация, когда бралось на веру визуальное состояние без
  реальной проверки рендеринга — с тех пор: описывать факт (например,
  "было отступов X, стало Y"), не утверждать "теперь идеально" без
  способа это проверить.
